# 角色與世界觀豐富度檢核表

這份清單對應 SKILL.md 的 Stage 2。目的不是要使用者一次填完一張問卷，而是給你（執行技能的 Claude）一份「別漏掉什麼」的地圖——每個面向都用幾個具體提問把使用者已經隱含但沒明講的設定挖出來，並且明確標出「這一項通常會餵給哪個欄位/世界書條目」，方便你在確認完之後知道要把資訊寫進卡片的哪裡。

跟使用者對話時，一次聚焦 1-2 個面向即可，避免列出七個大標題一次轟炸。可以用「已經有雛型了嗎？還是要我幫忙發想？」這種開放式問法，讓使用者選擇要親自寫還是要你提案。

## 1. 登場人物（開場即出現的核心角色）

- 除了使用者扮演的 `{{user}}` 和主角 `{{char}}`，開場場景裡還有誰會出現（哪怕只是背景路人也可能之後變成常駐 NPC）？
- 主角與 `{{user}}` 的初始關係設定是固定的（例如「一定是同事」），還是要讓使用者在對話開始時自訂身分（如 Ian 卡片示範的「職場後輩／獸醫實習生／自定義」三選一）？如果要讓使用者自訂，需要在 `system_prompt` 裡寫清楚「依使用者輸入身分決定初次相遇情境」的判斷邏輯。
- 對應輸出位置：`scenario`、`first_mes`/`alternate_greetings`、`system_prompt` 裡的開局判定邏輯。

## 2. 世界觀規則

- 時代與地點：架空還是現實？如果是現實地點，要不要刻意模糊化避免讀取使用者真實座標（常見做法：卡片裡明講「嚴禁讀取使用者現實地點」）？
- 這個世界跟現實有什麼不同的規則（魔法、超能力、特殊社會結構、职业設定的特殊性）？沒有奇幻元素也沒關係，「規則」也可以只是氛圍與基調（例如高壓都會 vs. 悠閒鄉村）。
- 反覆出現的環境感官細節：氣候、聲音、氣味、光線——這些細節如果設計得好，會變成貫穿全卡的風格錨點（Ian 卡的佛手柑木質調香氣、老狗爪子刮地板聲即是此類）。
- 對應輸出位置：`scenario`、世界書「世界觀氛圍」條目（通常設為 constant 常駐）。

## 3. 特殊事件

- 有沒有機率性觸發的隨機事件（例如「10% 機率觸發角色的某個小動作/小情緒波動」）？這類事件能讓長期互動不無聊。
- 有沒有關鍵劇情節點事件（例如季節性活動、角色生日、特定地點限定的邂逅)？
- 有沒有使用者可以主動觸發的事件（關鍵詞觸發，例如輸入特定詞句解鎖特殊互動、小遊戲——這個跟 Stage 5 的小遊戲設計會合流）？
- 對應輸出位置：世界書「隨機事件」條目、`system_prompt` 裡的事件判定邏輯。

## 4. 人物的情感／親密偏好

- 角色在情感關係中的依附傾向是什麼（安全型、焦慮型、逃避型……）？這會決定 ta 面對親密舉動時的預設反應模式。
- 角色有沒有明確的底線或雷點（例如「嚴格拒絕任何形式的暴力對待，會理性溝通後果斷離開」）？這類邊界設定能避免角色在互動中行為失真，也保護了創作意圖的一致性。
- 如果卡片涉及親密/成人向內容，角色的偏好、節奏、會讓 ta 卸下防備的觸發點是什麼？這些细节通常適合放進世界書的獨立條目（selective 觸發，避免每次都塞進上下文），只在情境需要時才注入。
- 對應輸出位置：`personality`、世界書「親密偏好」條目（建議設為關鍵詞觸發而非常駐）。

## 5. 背景故事

- 角色的過去經歷有哪些形塑了現在的性格？不需要寫成長篇傳記，抓 2-3 個關鍵事件即可，其餘留白讓互動中慢慢揭露（「深層設定，解鎖需要時間」是很好的懸念設計手法）。
- 有沒有「一開始藏起來、要靠玩家慢慢解鎖」的隱藏設定？如果有，要在 `system_prompt` 明確寫「反劇透原則」，禁止模型在旁白/對話中直接暴露這些關鍵詞或意圖，只能透過行為間接暗示。
- 對應輸出位置：`description`（可以做成分層：表層人設 + 加鎖的深層設定提示）、世界書「過去經歷」條目。

## 6. NPC 關係網

- 誰是角色的死黨/家人/同事/競爭對手？每個 NPC 適合各自建立一條世界書條目，並且思考「這個 NPC 在場時會如何影響主角的行為」（例如：家人在場會拆穿主角的偽裝、損友在場會讓主角卸下防備）。
- NPC 之間彼此有沒有關聯（同一個社交圈、共同回憶）？這能讓世界感覺更真實。
- 對應輸出位置：世界書逐條 NPC 條目（`selective`，用 NPC 姓名/暱稱/身分當關鍵詞）。

## 7. 角色心理狀態的進展脈絡

- 角色的心防/性格表現會不會隨好感度或劇情推進而變化？如果會，抓出 2-4 個階段（例如：完美偽裝期 → 動搖試探期 → 卸下防備期），並描述每個階段「表象」與「內心」的落差。
- 每個階段之間的轉換條件是什麼？靠好感度數值門檻（需要 MVU，見 Stage 4）還是靠劇情里程碑（不需要數值，靠模型自行判斷)？
- 有沒有「防止越級演繹」的需求？如果角色設計上很強調循序漸進（慢熱、傲嬌、心防重），要在 `system_prompt` 明講「嚴禁跳過前面階段直接演繹後期行為」。
- 對應輸出位置：`system_prompt` 裡的狀態機描述、（若使用 MVU）STATUS_DATA 的「關係階段」欄位。

## 快速確認用的總表格式

跟使用者對話時，可以用這種精簡表格同步進度（不用每次都完整列出七項，依實際討論到的範圍調整）：

| 面向 | 狀態 | 備註 |
|---|---|---|
| 登場人物 | ✅/🟡/⬜ | |
| 世界觀規則 | ✅/🟡/⬜ | |
| 特殊事件 | ✅/🟡/⬜ | |
| 情感／親密偏好 | ✅/🟡/⬜ | |
| 背景故事 | ✅/🟡/⬜ | |
| NPC 關係網 | ✅/🟡/⬜ | |
| 心理狀態進展脈絡 | ✅/🟡/⬜ | |
| 是否需要 MVU 動態變量卡 | ✅/🟡/⬜ | 見 variable-system.md |
