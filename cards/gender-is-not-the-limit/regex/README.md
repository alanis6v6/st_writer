# 花冠／尾卡 regex（第一版）

`scripts_wheel_footer.json` 是可以直接匯入 SillyTavern（角色卡 → Advanced Definitions → Regex Scripts）的三條腳本：

| scriptName | 對應的輸出標籤 |
|---|---|
| `RT_頭卡` | `[HEAD]...[/HEAD]` |
| `RT_正文` | `[BODY]...[/BODY]` |
| `RT_花冠尾卡` | `[WHEEL]...[/WHEEL]` 到 `[FOOT]...[/FOOT]`（兩個標籤一起吃，因為花冠需要讀到尾卡裡的好感度數字） |

加上 `scripts_minigames.json`（記憶配對／探索發現兩個小遊戲，來自另一輪測試，格式相同可直接合併）。

## 運作方式

- 三個角色的花冠六階段文字（羅馬數字／階段名／備註）全部固定寫死在 regex 裡，**目前是第幾階段完全靠 `M:`／`T:`／`L:` 的數字用正規表達式的數字範圍比對算出來**，不需要 AI 每輪額外輸出。
- ⚠️ **門檻不是三人共用同一組**：馬提亞斯是 0-19/20-39/40-59/60-74/75-89/90-100，
  阿霆與 Lia 是 0-19/20-39/**40-54/55-69/70-84/85-100**（後段切得比較密）。
  `build_wheel_footer.py` 裡的 `THRESHOLDS` 字典分開定義，`int_range_regex()` 用純
  數字比對（不是算術）產生對應的 regex——改門檻只要改這個字典，不要手動兜 regex。
- **卡片寬度比照參考卡（Ian）的標準**：`max-width:420px`（花冠 `min(78vw,340px)`）。
  之前用的 650-760px 是照桌機螢幕抓的，在手機聊天欄裡太寬，會把格線擠壓變形。
- **外框拆成頭卡／尾卡各自獨立的「書擋」卡片**（`.rt-frame`，金色雙框＋四角花紋），
  中間的正文與花冠不再被框住。原本整段訊息包在同一個外框裡，但每個使用者的正文
  字數落差很大（幾百字到 1200+ 字都有），單一外框要嘛看起來空、要嘛被撐開變形。
  拆開後正文可以是任何長度，頭尾兩張卡片的花紋不受影響。`.rt-scope` 是一個看不見
  的包裹層（只負責 box-sizing 重置與字型），撐住 `~` 兄弟選擇器需要的 DOM 結構，
  但本身沒有邊框/背景。
- **點頭像切換要看誰的花冠與衣著，預設值改成從 `[WHEEL]` 的 `LABEL:` 判斷**（不是
  `[HEAD]` 的 `FOCUS:` 欄位）。原因：`FOCUS:` 在多人同場時會寫「群戲」而不是指名
  某個角色（這是 `system_prompt.md` `<Focus_Engine>` 規則裡本來就有的合法值），
  舊版 regex 硬性要求 `FOCUS:` 出現三個名字之一，遇到「群戲」整條 `RT_頭卡` 直接
  比對失敗——連帶讓共用的 `<style>` 區塊（只在這條 regex 裡輸出一次）整個消失，
  這正是使用者實測回報「P.2 之後沒吃到美化框」的根因。`LABEL:` 一定會是三人各自
  六個階段用詞其中之一（18 個詞彼此不重複），不管是不是群戲場景都能準確判斷。
  點擊哪個頭像則由 CSS radio + `:not(:empty)`／`:has()` 技巧驅動，沒有 JavaScript。
- 尾卡包在 `<details>` 裡，可以收合。
- 「心事」旁的圓形頭像會顯示**當輪焦點角色**的照片（不是固定符號，也不跟著頭像切換走——VOICE／MOOD 本來就只跟著敘事焦點）。
- 尾卡新增「姿勢」欄位（`U_POSE`/`M_POSE`/`T_POSE`/`L_POSE`），跟衣著一樣是「你固定顯示、三人切換顯示」，但**不受衣著連續性規則約束**——姿勢本來就該每輪自然變化，不需要跟上一輪一致。

## 重新產生 JSON

不要手動改 `scripts_wheel_footer.json`——改 `build_wheel_footer.py`（版面配置、文字內容、CSS 都在裡面）然後重新跑：

```
python3 build_wheel_footer.py
```

`avatars/*.b64` 是三人頭像的 base64（128px JPEG），會被內嵌進 regex 輸出裡。

## 測試

`simulate.py` 用 Python 模擬 SillyTavern 的 `String.replace($1$2...)` 行為，對每個角色各自的 18 組好感度邊界值、18 個花冠階段用詞（LABEL）、「群戲」FOCUS 的邊角案例、以及 5 個開局的真實內容跑過，確認花冠階段判定（含馬提亞斯與阿霆／Lia 不同的門檻表）、頭像預設焦點、HTML 標籤配對都正確：

```
python3 simulate.py
```

## 已知限制（曾經是 bug，現在改用 `:has()` 解決）

頭像切換原本用 `id`/`for`（`rtf-m`/`rtf-t`/`rtf-l`）連結，但這組標籤在**每一則訊息**都會逐字重複輸出——HTML 的 id 理論上整頁要唯一，`label[for]` 綁定會抓「整個頁面第一個」該 id 的元素，不是視覺上鄰近的那個，所以在很長的對話串裡點頭像常常沒反應（其實是切到別則訊息看不到的地方去了）。

現在改成：radio 直接包在自己的 `<label>` 裡面（不用 id/for 就能點擊觸發），CSS 改用 `.rt-focus-switch:has(.av-m input:checked) ~ ...` 從外面搆到花冠／尾卡區塊。`:has()` 在主流瀏覽器引擎已經穩定支援多年，這裡放心使用。radio 的 `name` 屬性仍然用 M/T/L 數字當種子（例如 `rt-focus-889220`）降低跨訊息的分組互相影響，但這只是次要的體感改善，不是必要修復——真正解決「點了沒反應」的是 `:has()` 這個改動。

## 已解決：「P.2 之後沒吃到美化框」

實測回報的原始訊息裡 `FOCUS: 今日焦點・群戲`——不是三個角色名字之一。舊版
`RT_頭卡` 的 findRegex 要求 `FOCUS:` 一定要出現「馬提亞斯」「阿霆」「Lia／莉亞」
三者之一才會比對成功，「群戲」讓它直接比對失敗；因為共用的 `<style>` 區塊只從
`RT_頭卡` 輸出一次，`RT_頭卡` 沒吃到，整則訊息就沒有樣式可用。已改成 `RT_頭卡`
不再要求 `FOCUS:` 指名任何人，預設頭像改用 `[WHEEL]` 的 `LABEL:` 判斷（見上方
「運作方式」）。用使用者提供的那則原始訊息＋新增的姿勢欄位重新測試，三條 regex
都正確比對，已寫進 `simulate.py` 的固定測試案例（`群戲` FOCUS + 18 個 LABEL 詞
全部個別驗證一輪）。
